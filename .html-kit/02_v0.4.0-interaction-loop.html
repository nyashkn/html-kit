§2Search engine for ⌘K — three options

Recommended
~70 KB · html-native

Pagefind

Pros
  • Built-in <pagefind-modal-ui> with ⌘K binding out of box
  • HTML-native indexer — feed it the artifact dir, done
  • Snippet + highlight matching across all NN_*.html
Cons
  • Sharded fetch can be flaky over file:// — must serve via daemon
  • ~70 KB JS payload, not tiny
Strong alt
~10 KB · pure JS

Orama

Pros
  • Pure JS in-memory — no shard fetch, no CORS surface
  • ~10 KB; fits inside the daemon-served HTML directly
  • BM25 + typo tolerance, fast
Cons
  • ⌘K modal is DIY — ~30 lines of vanilla JS to wire
  • No built-in highlight component; roll our own
Fallback
rust/wasm · small

Stork

Pros
  • Rust → WASM, smaller payload than Pagefind
  • Genuinely fast at query time
Cons
  • Less actively maintained (stale releases through 2025)
  • Same shard/CORS shape as Pagefind — no net win
  • DIY ⌘K modal still required

Verdict Start with Pagefind: the daemon already serves over HTTP so the shard-fetch CORS issue is moot, and the bundled modal-UI removes a whole DIY surface. Reserve Orama as the fallback if Pagefind's index rebuild becomes a hot loop at 10 sessions × 100 artifacts.

§3Deep detail

Daemon lifecycle bun · launchd · pid lock

Singleton daemon on port :7879. PID-locked to prevent double-start across 10 concurrent agent sessions. Optional launchd plist for auto-start at login.

# bun run html-kit:up
import { existsSync, writeFileSync, readFileSync } from "fs";
const PID = "~/.html-kit/_daemon/daemon.pid";
const PORT = 7879;

if (existsSync(PID)) {
  const pid = parseInt(readFileSync(PID, "utf8"));
  try { process.kill(pid, 0); exit(0); } // already running
  catch { /* stale pid, fall through */ }
}

writeFileSync(PID, String(process.pid));
Bun.serve({ port: PORT, fetch: router });
// fs.watch(~/Documents/**/.html-kit/) → debounce 200ms → pagefind reindex → SSE broadcast

Optional ~/Library/LaunchAgents/dev.html-kit.daemon.plist with RunAtLoad=true and KeepAlive on crash.

Annotation JSONL schema append-only · sibling file

One record per line in NN_slug.html.annotations.jsonl, written by the daemon on each POST. Cursor = byte offset, monotonic per file.

{"ts":"2026-05-19T14:22:01Z", "kind":"approve", "target":"#section-2", "by":"kn"}
{"ts":"2026-05-19T14:22:18Z", "kind":"reject", "target":"[data-component=tldr-flow-strip]", "note":"too many nodes — cap at 5"}
{"ts":"2026-05-19T14:23:04Z", "kind":"comment", "target":".card:nth-of-type(2)", "note":"recommend Orama; size argument decisive"}
  • kind: approve | reject | comment
  • target: CSS selector OR data-component attribute value
  • Agent reads with GET /api/annotations/<path>?since=<byte>; daemon returns delta + new cursor.
10-session concurrency model singleton + posix append

Up to 10 Claude Code sessions can render concurrently into ~/Documents/**/.html-kit/. No app-level locking needed.

  • One daemon, many writers. Daemon is the only HTTP listener (port 7879, PID-locked). Agent sessions never bind ports — they only spawn renders via /html-kit skill.
  • Disjoint filenames. resolve-out-path.ts picks NN_*.html with monotonic NN per directory; collisions resolved by next-number scan. Two agents racing the same number is a non-issue because O_CREAT | O_EXCL retries.
  • Annotation appends. POSIX guarantees O_APPEND writes ≤ PIPE_BUF (4 KB on macOS) are atomic across processes. Each JSONL record is well under that. No locks, no rotation.
  • Index coherence. Pagefind reindex is debounced 200 ms after the last fs event, so a burst of 10 simultaneous renders triggers one rebuild, not ten.
Failure modes degraded · recovery
  • Daemon down. Agent's POST /api/annotate from browser fails → toast "daemon offline". Agent's drain on next turn returns empty → falls back to chat-msg feedback path (dotted edge in §1).
  • Port conflict. Something else on 7879 → daemon exits with clear stderr; user runs lsof -i :7879 and either kills the squatter or sets HTML_KIT_PORT.
  • Stale PID. Previous daemon crashed without cleanup → fresh start detects pid not alive (kill -0), overwrites PID file, continues. No manual recovery.
  • Browser tab orphaned. User left a v1 tab open while agent emitted v2 → tab's SSE channel includes the v2 path; banner appears: "newer revision available · open NN+1_slug-v2.html". One click swap, no data loss (annotations already flushed).
